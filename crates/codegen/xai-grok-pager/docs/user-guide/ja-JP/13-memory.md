# セッション間メモリ

メモリを使うと、Grok は以前のセッションでの事実、決定、パターンを思い出せます。保存した情報は Grok によりインデックス化され、自動的に検索されるため、新しいセッションでも関連するコンテキストを再利用できます。

---

## メモリとは？

メモリがなければ、各 Grok セッションはまっさらな状態で始まります。モデルは以前のセッションについて何も知りません。メモリを有効にすると、Grok は次のことを行えます。

- 以前に説明したプロジェクトの慣例を思い出す。
- 効果があったデバッグ手順を再利用する。
- アーキテクチャ上の決定をセッション間で引き継ぐ。
- すでに答えを持っている質問を再度尋ねないようにする。

メモリは実験的機能であり、デフォルトでは無効です。

---

## メモリを有効にする

### セッションごとのフラグ

```bash
grok --experimental-memory
```

### 環境変数

```bash
export GROK_MEMORY=1
grok
```

### 設定ファイル（永続）

```toml
# ~/.grok/config.toml
[memory]
enabled = true
```

### 強制的に無効化する

他の設定でメモリが有効になっていても無効にするには、次を実行します。

```bash
grok --no-memory
```

または:

```bash
export GROK_MEMORY=0
```

`--no-memory` フラグは絶対的に最優先され、常にメモリを無効にします。

### セッション中の切り替え

再起動せずに、セッション中にメモリのオン・オフを切り替えます。

```
/memory on
/memory off
```

この切り替えはセッション単位です。`config.toml` には保存されません。オフにするとメモリツールへのアクセスはなくなりますが、ディスク上の既存ファイルは保持されます。オンにするとメモリストレージが再初期化され、メモリツールが登録されます。

`/memory` モーダル内で `t` を押して切り替えることもできます。

### 優先順位

1. `--no-memory` CLI フラグ（常に無効化）
2. `--experimental-memory` CLI フラグ（有効化）
3. `GROK_MEMORY` 環境変数: `1`/`true` で有効化、`0`/`false` で無効化
4. config.toml の `[memory]` セクション
5. デフォルト: 無効

## メモリの保存方法

メモリは `~/.grok/memory/` 配下に Markdown ファイルとして保存されます。

| 場所 | スコープ | 説明 |
|----------|-------|-------------|
| `~/.grok/memory/MEMORY.md` | グローバル | すべてのプロジェクトに適用される事実 |
| `~/.grok/memory/<project-slug>-<hash8>/MEMORY.md` | ワークスペース | プロジェクト固有の慣例とコンテキスト |
| `~/.grok/memory/<project-slug>-<hash8>/sessions/` | セッション | セッションごとの要約とログ |

Grok は各ワークスペースディレクトリの末尾に、リポジトリの識別子の短いハッシュを付加します。ディレクトリが `origin` リモートを持つ Git リポジトリの場合、識別子は `org/repo` 形式の `origin` リモートです。それ以外の場合はディレクトリパスが使用されます。同じリポジトリのクローンと worktree は同じ `origin` リモートを共有するため、1 つのメモリディレクトリも共有します。

SQLite インデックスは、すべてのメモリファイルを横断するハイブリッド検索をサポートします。
- **FTS5** は、キーワード照合のための全文検索を提供します。
- **vec0** は、意味的な類似性のためのベクトル検索を提供します。ベクトル検索は任意であり、embedding が必要です。

## 自動保存

セッションが終了すると、Grok は構造化されたメタデータ要約をそのセッションの日次ログに保存します。この要約には次が含まれます。

- メッセージ数（ユーザー、アシスタント、ツール結果）。
- トピック: セッション内の実質的な最初の数件のユーザープロンプト（最大 5 件）。
- セッション日時（UTC）。

Grok は追加のレイテンシや LLM 呼び出しなしに、会話メタデータから要約を作成します。実質的なプロンプトが 3 件未満、またはユーザーテキストが 50 バイト未満の些細なセッションでは保存をスキップします。

要約にはツール使用状況、ファイルパス、シェルコマンドは記録されません。セッション ID はログファイル名の一部になります。自動保存をオフにするには、`session.save_on_end = false` を設定します。決定、パターン、推論をより詳細に記録するには、`/flush` を使用してください。

---

## /flush による詳細な知識の保存

決定、パターン、デバッグワークフロー、API の発見といった詳細な記録には、TUI で `/flush` を使用します。

```
/flush
```

これにより、現在のセッションで最も重要な内容を LLM が要約し、日付付きのセッションログに書き込みます。要約はインデックス化され、今後のセッションで検索できます。

重要なコンテキストを保持したい場合は `/flush` を使用します。
- compaction 前（古い会話ターンが破棄されるため）
- 生産的なデバッグセッションの終了時
- 重要なパターンや慣例を発見した後

## メモリを使う

### 記憶する

何かを記憶するよう Grok に依頼すると、プロジェクト固有の項目はワークスペースの `MEMORY.md` ファイルに、プロジェクト横断の設定はグローバルの `~/.grok/memory/MEMORY.md` に追記されます。

```
> remember to always open PR links after pushing
```

Grok は、`## Preferences`、`## Project Context`、`## Debugging` などの整理された見出しの下に、永続的な記述としてエントリを記録します。ファイルウォッチャーは次回のメモリ検索時に変更を再インデックス化するため、新しいエントリは現在のセッション内で検索可能になります。

`/remember` コマンドでメモを直接保存することもできます。

```
/remember always open PR links after pushing
```

テキストなしで `/remember` を実行すると、次に入力する行がメモになる記憶モードに入ります。どちらの場合も、Grok はメモを表示するレビュー画面を開きます（`Tab` で切り替え可能な任意の書き換え版もあります）。確認するまでメモは書き込まれません。保存時には、Grok は `Memory saved to ~/.grok/memory/MEMORY.md` と表示します。

### 忘れる

何かを忘れるよう Grok に依頼すると、一致するエントリを見つけて削除します。

```
> forget the snake_case convention
```

忘却はベストエフォートです。モデルはメモリを検索し、一致するエントリを削除します。確実に削除するには、`~/.grok/memory/` 配下のファイルを直接編集して、自分でエントリを削除してください。ファイルの場所を特定するには、`/memory` ブラウザーを開き、`y` を押してパスをコピーします。

### 思い出す

Grok が何を覚えているかを尋ねます。

```
> what do you remember?
```

Grok はすべてのメモリファイルを検索し、グローバル設定、プロジェクト固有の知識、セッション履歴というソース別に、把握している内容を要約します。生のファイルを閲覧するには `/memory` を使用してください。

### 直接編集

`~/.grok/memory/` 配下のメモリファイルは直接編集できます。ファイルウォッチャーは、次回のメモリ検索時に変更を再インデックス化します。現在のセッションを今すぐ保存するには `/flush` を、セッションログを整理されたトピックに統合するには `/dream` を使用します。

## /memory によるメモリの閲覧

`/memory` コマンドを実行すると、すべてのメモリファイルを表示するモーダルが開きます。

```
/memory
```

ファイルはスコープ別にグループ化されます。
- **グローバル** -- プロジェクト横断のメモリ（`MEMORY.md`）。
- **ワークスペース** -- プロジェクト固有のメモリ（`MEMORY.md`）。
- **セッション** -- セッションごとの要約（新しい順）。

モーダルは分割ペインレイアウトを使用します。左側にファイル一覧、右側に読み取り専用の内容プレビューが表示されます。一覧内を移動するとプレビューが更新されます。

### キーボードショートカット

| キー | 操作 |
|-----|--------|
| `↑`/`↓` または `j`/`k` | ファイル一覧を移動 |
| `PgUp`/`PgDn` | 10 エントリ移動 |
| `/` | ファイル一覧を絞り込み |
| `y` | 選択中ファイルのパスをクリップボードにコピー |
| `x` | 選択中のセッションファイルを削除（確認のため、もう一度 `x` を押す） |
| `t` | メモリのオン・オフを切り替え |
| `Ctrl+F` | 全画面表示を切り替え |
| `Esc` | モーダルを閉じる、またはフィルターモードを終了 |

プレビューペインは読み取り専用です。マウスホイールまたはスクロールバーをドラッグしてスクロールします。削除できるのはセッションファイルのみで、グローバルまたはワークスペースの `MEMORY.md` は削除できません。

メモリモーダルの内容領域が 80 列未満の場合、モーダルはプレビューペインを隠し、ファイル一覧のみを表示します。

コマンドパレットから `/memory` を開くこともできます。

## メモリ通知

`/remember` でメモを保存すると、Grok はスクロールバックで確認を表示します。

```
Memory saved to ~/.grok/memory/MEMORY.md
```

バックグラウンドでの保存（flush、dream、セッション終了時）は静かに実行され、スクロールバックメッセージは投稿されません。Grok が保存した内容はいつでも `/memory` で閲覧できます。

## /dream による Dream 統合

`/dream` コマンドは、分散したメモリの断片を整理されたトピックへ統合します。

```
/dream
```

Dream は個々のセッションログとメモリエントリを一貫性のある重複排除済みのナレッジベースに再編成します。これによりノイズが減り、時間とともに検索品質が向上します。`/dream` を使用するには、メモリが有効である必要があります。

### 自動 Dream

Dream は自動でも実行されます。デフォルトでは、Grok はセッション終了時に統合条件を確認し、十分な時間が経過して十分なセッションが蓄積されていれば Dream を実行します。

```toml
[memory.dream]
enabled = true     # 自動統合を実行する（デフォルト: true）
min_hours = 4      # 統合間の最小時間（時）
min_sessions = 3   # 前回の統合以降の最小セッション数
# check_interval_secs はデフォルトで未設定のため、Dream はセッション終了時にのみ実行されます。
# 定期的な間隔でも確認するには、正の秒数を設定します。
```

## メモリがプロンプトに与える影響

### 最初のターンへの注入

各セッションの最初のターンで、Grok は現在のプロジェクトに関連するコンテンツをメモリから自動的に検索し、コンテキストとして注入します。これにより、Grok はリマインダーなしで以前のセッションの知識を持って開始します。

最初のターンへの注入は設定できます。

```toml
[memory.initial_injection]
enabled = true     # 最初のターンへの注入を有効または無効にする
min_score = 0.0    # 任意のスコアしきい値。デフォルトでは未設定であり、フィルタリングは行われません
```

### Compaction 後

自動 compaction の後にも、破棄された可能性がある関連コンテキストを復元するため、メモリが検索されます。

## メモリ検索

Grok はメモリを自動的に検索しますが、チャットで手動検索を実行することもできます。

```
Search memory for "auth middleware patterns"
Read my workspace MEMORY.md
```

モデルは次の 2 つのメモリツールにアクセスできます。
- `memory_search` -- すべてのメモリを横断するハイブリッド検索（ベクトル + 全文）
- `memory_get` -- パスで指定したメモリファイルを読み取る

### ハイブリッドスコアリング

メモリ検索は、次の重み付き組み合わせを使用します。
- **ベクトル類似度**（意味的） -- 重み: 0.7
- **BM25 テキスト類似度**（キーワード） -- 重み: 0.3

結果は最小スコアしきい値（デフォルト: 0.35）でフィルタリングされます。

### ソースの重み

各メモリソースには、スコアに適用される重み倍率があります。すべてのソースのデフォルトは `1.0` であり、`[memory.search.source_weights]` 配下で任意の値を調整できます。

| ソース | 重み | 説明 |
|--------|--------|-------------|
| `workspace` | 1.0 | プロジェクト固有のメモリ |
| `session` | 1.0 | セッションログ |
| `global` | 1.0 | プロジェクト横断のメモリ |

### 時間的減衰

セッションメモリは時間とともに減衰するため、最近のセッションが優先されます。

```toml
[memory.search.temporal_decay]
enabled = true           # 時間ベースの減衰を有効にする
half_life_days = 7.0     # この日数が経過するとスコアが半減する
```

減衰するのはセッションチャンクのみです。グローバルメモリとワークスペースメモリは厳選された長期知識を含むため、対象外です。

### MMR（Maximal Marginal Relevance）

MMR の再ランキングは、冗長な結果にペナルティを課して多様性を高めます。

```toml
[memory.search.mmr]
enabled = false          # 多様性を高める再ランキングをオプトインで有効化
lambda = 0.7             # 0.0 = 最大の多様性、1.0 = 純粋な関連性
```

## CLI コマンド

`grok memory` コマンドは、シェルからメモリを管理します。サブコマンドは `clear` の 1 つです。

```bash
# ワークスペースメモリを消去（MEMORY.md、sessions/、index.sqlite）。これがデフォルトのスコープです。
grok memory clear

# 同じスコープを明示的に指定
grok memory clear --workspace

# グローバル MEMORY.md を消去
grok memory clear --global

# ワークスペースとグローバル両方のメモリを消去
grok memory clear --all

# 確認プロンプトをスキップ（-y は短縮形）
grok memory clear --yes
```

シェルからメモリを編集するには、エディターでファイルを直接開きます。例: `$EDITOR ~/.grok/memory/MEMORY.md`。

## 設定リファレンス

### コア設定（`[memory]`）

| キー | デフォルト | 説明 |
|-----|---------|-------------|
| `enabled` | `false` | メモリを有効にする |
| `session.save_on_end` | `true` | セッション終了時にメタデータ要約を書き込む |
| `watcher.enabled` | `true` | `~/.grok/memory/` の外部編集を監視して再インデックス化する |

### インデックス設定（`[memory.index]`）

| キー | デフォルト | 説明 |
|-----|---------|-------------|
| `max_chunk_chars` | `1600` | 最大チャンクサイズ（文字数） |
| `chunk_overlap_chars` | `320` | チャンク間で重複させる文字数 |

### Embedding 設定（`[memory.embedding]`）

| キー | デフォルト | 説明 |
|-----|---------|-------------|
| `provider` | `"api"` | Embedding プロバイダー（現在は `"api"`） |
| `model` | *(プロバイダーのデフォルト)* | Embedding モデル名 |
| `dimensions` | `1024` | Embedding ベクトルの次元数 |

### 検索設定（`[memory.search]`）

| キー | デフォルト | 説明 |
|-----|---------|-------------|
| `max_results` | `6` | 最大検索結果数 |
| `min_score` | `0.35` | 最小関連性スコア |
| `vector_weight` | `0.7` | ベクトル類似度の重み |
| `text_weight` | `0.3` | BM25 テキスト類似度の重み |

### 初回注入設定（`[memory.initial_injection]`）

| キー | デフォルト | 説明 |
|-----|---------|-------------|
| `enabled` | `true` | 最初のターンへのメモリ注入を有効にする |
| `min_score` | 未設定 | 最初のターンの結果に対するスコアしきい値。未設定の場合、Grok はしきい値を適用しません。これは `0.0` と同等です。 |

### Dream 設定（`[memory.dream]`）

| キー | デフォルト | 説明 |
|-----|---------|-------------|
| `enabled` | `true` | 自動 Dream 統合を有効にする |
| `min_hours` | `4` | 統合間の最小時間（時） |
| `min_sessions` | `3` | 前回の統合以降の最小セッション数 |
| `stale_lock_secs` | `3600` | 古い統合ロックを回収するまでの秒数 |
| `check_interval_secs` | 未設定 | 定期確認の間隔（秒）。未設定の場合、Dream はセッション終了時にのみ実行されます。 |

### Flush 設定（`[compaction.memory_flush]`）

flush は compaction の動作であるため、`[memory]` ではなく `[compaction]` 配下で設定します。

| キー | デフォルト | 説明 |
|-----|---------|-------------|
| `enabled` | `true` | compaction 前のメモリ flush を有効にする |
| `soft_threshold_tokens` | `4000` | flush をトリガーする、compaction しきい値前のトークン余裕量 |
| `max_flush_write_chars` | `8000` | flush がメモリに書き込める最大文字数 |
| `flush_model` | 未設定 | flush ターンのモデル。未設定の場合、Grok はセッションのプライマリモデルを使用します。 |
| `idle_timeout_secs` | 未設定 | バックグラウンド flush 前のアイドル秒数。未設定の場合、flush は compaction 前にのみ実行されます。 |
| `semantic_dedup_threshold` | 未設定 | flush した内容を重複排除するコサイン類似度しきい値。未設定の場合、デフォルトは `0.92` です。 |

### Pruning 設定（`[compaction.pruning]`）

pruning は compaction の動作であるため、`[memory]` ではなく `[compaction]` 配下で設定します。

| キー | デフォルト | 説明 |
|-----|---------|-------------|
| `enabled` | `true` | ツール結果の pruning を有効にする |
| `keep_last_n_turns` | `3` | ツール結果を決して pruning しない直近ターン数 |
| `soft_trim_threshold` | `4000` | 古いツール結果をソフトトリミングする文字数しきい値 |
| `soft_trim_head` | `1500` | ソフトトリミングした結果の先頭から保持する文字数 |
| `soft_trim_tail` | `1500` | ソフトトリミングした結果の末尾から保持する文字数 |
| `hard_clear_age_turns` | `10` | ツール結果をプレースホルダーに置き換えるターン経過数 |

## メモリの鮮度

セッションメモリが古い場合、Grok は検索結果に鮮度に関する注記を付けます。古い結果ほど、それを信頼する前に現在の状態を確認するよう強く促されます。これらの注記は、正確ではなくなった可能性のある保存済みの事実を見つける助けになります。グローバルメモリとワークスペースメモリは厳選された長期知識を保持するため、鮮度に関する注記は付けられません。

---

## ファイルウォッチャー

デフォルトでは、Grok は `~/.grok/memory/` にある外部ファイルの変更を監視します。メモリファイルを直接編集した場合（例: エディター内）、次のメモリ検索時に変更が自動的に反映されます。

- 作成または変更されたファイルは再インデックス化されます。
- 削除されたファイルの古いチャンクはインデックスから削除されます。

```toml
[memory.watcher]
enabled = true    # デフォルト
```

## トラブルシューティング

### メモリが機能しない

1. メモリが有効か確認する: `grok inspect` の出力を確認します。
2. フラグを確認する: `grok --experimental-memory` または `GROK_MEMORY=1`。
3. `--no-memory` または `GROK_MEMORY=0` が設定を上書きしていないか確認する。

### セッションでメモリが表示されない

メモリは最初のターンで注入されます。メモリを有効にする前にセッションを開始した場合は、`/new` で新しいセッションを開始してください。

### メモリファイルを表示する

TUI の `/memory` を使用して、プレビュー付きで全メモリファイルを閲覧します。直接アクセスすることもできます。

```bash
ls ~/.grok/memory/
cat ~/.grok/memory/MEMORY.md
$EDITOR ~/.grok/memory/MEMORY.md
```

### デバッグログ

```bash
RUST_LOG=debug GROK_LOG_FILE=/tmp/grok.log grok
grep "memory" /tmp/grok.log
```
