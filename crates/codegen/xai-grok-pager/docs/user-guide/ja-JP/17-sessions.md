# セッション管理

Grok はすべての会話を自動的にディスクへ保存します。TUI、ヘッドレスモード、agent stdio のいずれを使用していても、Grok はやり取りをセッションとして記録します。セッションは再開、巻き戻し、圧縮できます。このドキュメントでは、セッションの管理方法について説明します。

---

## セッションとは

セッションとは、完全な履歴を持つ永続的な会話です。次の情報が含まれます。

- すべてのユーザープロンプトとエージェントの応答
- ツール呼び出しとその結果
- TODO/タスクリストの状態
- 巻き戻し用のファイルスナップショット
- トークン使用量とターン数
- サブエージェントのセッション（有効な場合）

セッションは一意のセッション ID（Grok が生成する場合は UUIDv7。クライアントは `-s` で独自の ID を指定可能）で識別され、`~/.grok/sessions/` 以下のディスクに保存されます。ベースディレクトリを変更するには `GROK_HOME` を設定します。未設定の場合、Grok は `~/.grok` を使用します。

---

## ストレージ構成

Grok は各セッションを個別のディレクトリに保存し、作業ディレクトリごとにグループ化します。グループ名には、作業ディレクトリを URL エンコードした値を使用します。エンコード後の名前が 255 バイトを超える場合は、代わりにスラッグとハッシュを使用し、元のパスをグループ内の `.cwd` ファイルに記録します。

```
~/.grok/sessions/<encoded-cwd>/<session-id>/
  summary.json            # メタデータ: 要約/タイトル、タイムスタンプ、モデル ID、メッセージ数
  updates.jsonl           # ACP セッション更新ストリーム（会話 + ツール呼び出し）
  chat_history.jsonl      # モデルに送信された未加工のチャットメッセージ
  plan.json               # TODO/タスクリストの状態
  rewind_points.jsonl     # /rewind による取り消し用のファイルスナップショット
  signals.json            # セッションシグナル（トークン使用量、ツール/ターンのカウンター）
  feedback.jsonl          # ユーザーのフィードバックと評価
  compaction_checkpoints/ # 圧縮（手動または自動）で保存された状態
  subagents/              # サブエージェントごとのメタデータ（meta.json）。子セッションは通常のセッションツリー内に保存される
```

`summary.json` はインデックスエントリです。セッションの要約と生成されたタイトル、モデル ID、作成・更新日時、メッセージ数、フォークまたは復元されたセッションの親セッション参照を記録します。`updates.jsonl` は、`/resume` とセッション復元の基礎となる正規の会話ログです。

## セッションの開始と終了

### 新しいセッション

TUI は起動するたびに新しいセッションを作成します。セッションの途中で明示的に新しく始めるには、次を実行します。

```
/new
```

これにより現在のコンテキストが消去され、新しい会話が始まります。エイリアス: `/clear`。

### 終了

セッションを終了して Grok を閉じるには、次を実行します。

```
/quit
```

エイリアス: `/exit`。Grok を閉じずに現在のセッションから離れるには、`/home` を使用してウェルカム画面に戻ります。

---

## セッションの再開

### TUI から

以前のセッションを参照して再開するには、`/resume` コマンドを使用します。

```
/resume
```

現在のワークスペースの最近のセッションを一覧表示するセッションピッカーが開きます。再開するセッションを選択してください。このコマンドは引数を取りません。

ピッカーに入力すると、タイトルで一覧を絞り込むと同時に、入力に応じて会話内容も検索されます。内容が一致した結果は「Extended search results」という見出しの下に表示されます。短い待ち時間を設けずに即座に検索するには、`Ctrl+/` を押します。

現在アクティブなセッション（親セッションとすべてのフォーク）の切り替え、名前変更、終了には、代わりに `/dashboard`（またはエイリアスの `/sessions`）を使用します。

### コマンドラインから

ID を指定して特定のセッションを再開します。

```bash
grok --resume <session-id>
```

ID を指定せずに `grok --resume` を実行すると、現在のディレクトリで最も新しいセッションを再開します。

### ウェルカム画面から

`grok` を起動すると、ウェルカム画面に現在のディレクトリの最近のセッションが一覧表示されます。再開するセッションを選択してください。

---

## セッションのフォークと名前変更

### フォーク

会話のコピーから開始する同等のエージェントとして、現在のセッションを分岐します。

```
/fork [--worktree|--no-worktree] [directive]
```

任意の `directive` を渡すと、新しいセッションの最初のプロンプトを設定できます。フォークを新しい git worktree で実行するかどうかは、`--worktree` または `--no-worktree` で選択します。どちらも省略すると、毎回確認されます。このバージョンでは `--at <turn>` フラグはサポートされていません。

### 名前変更

現在のセッションのタイトルを変更します。

```
/rename <title>
```

エイリアス: `/title`。

---

## /rewind コマンド

`/rewind` は、会話中の以前の時点の状態にファイルを復元して、直近の変更を取り消します。ミスから復旧する際に使用します。

```
/rewind
```

`/rewind` を実行すると（またはアイドル状態でプロンプトが空かつ会話メッセージがあるときに、800ms 以内に **Esc Esc** を押すと）、Grok は次の処理を行います。

1. 巻き戻しポイントの一覧を表示する（ユーザープロンプトごとに 1 つ）
2. 巻き戻すポイントを選択できるようにする
3. その時点の状態にすべてのファイルを復元する
4. 会話履歴をその時点までに切り詰める

ファイルのスナップショットはプロンプトごとに記録されるため、以前のどの状態にも戻れます。

**重要:** `/rewind` はディスク上のファイルを変更します。取り消された変更は、git に保存していない限り失われます。

---

## /compact コマンド

`/compact` は会話履歴を圧縮し、コンテキストウィンドウの使用量を抑えます。初期のメッセージが不要になった長いセッションで使用します。

```
/compact
/compact [context]
```

任意の `context` 引数を使用すると、圧縮時に保持する内容について追加の指示を指定できます。

### 自動圧縮

コンテキストウィンドウが上限に近づくと、Grok は会話を自動的に圧縮します。自動圧縮が実行されると通知が表示されます。このしきい値に達するタイミングは、モデル設定の `context_window` 設定で制御します。

---

## /session-info コマンド

現在のセッションの詳細を表示します。

```
/session-info
```

次の情報が表示されます。

- セッションタイトル（設定されている場合）
- Shell バージョン
- セッション ID
- 作業ディレクトリ
- モデル（コーディングモデルの場合はモデルハッシュを含む）
- API バックエンドとサンドボックスプロファイル（設定されている場合）
- コンテキストウィンドウの使用量（使用済みトークン数、総トークン数、使用率）

## ヘッドレスモードでのセッション管理

ヘッドレスモードでは、コマンドラインフラグを使用してセッションを管理します。

```bash
# 毎回新しいセッション（デフォルト）
grok -p "Hello"

# ID を指定して既存のセッションを再開（存在しない場合はエラー）
grok -p "Continue where we left off" -r <session-id>

# 現在のディレクトリで最も新しいセッションを継続
grok -p "What were we doing?" -c
```

ヘッドレスモードでは、`-r`/`--resume` で既存のセッションを再開します。セッションが存在しない場合はエラーになります。または、`-c`/`--continue` で現在のディレクトリの最も新しいセッションを継続します。JSON 出力から取得したセッション ID（下記参照）を `-r` に渡します。

`-s`/`--session-id` は、**UUID** を指定して新しいセッションを**作成**する場合にのみ使用します（値が UUID でない場合、または対象のセッションディレクトリにその ID のセッションがすでに存在する場合はエラー）。既存のセッションは再開されません。`-s` で既存セッションを再開するのは、以前の非公開 upsert 動作でした。代わりに `-r`/`-c` を使用してください。`-s` と `-r`/`-c` を組み合わせるのは、`--fork-session` も渡す場合に限ります（履歴を新しい ID にフォークし、任意の `-s` で子の UUID を指定します）。これは Claude Code の上書き防止モデルと同様です（書き込み先 cwd でクライアントが事前確認を行うため、逐次使用は確実ですが、同じ ID の同時使用はベストエフォートです）。

セッション ID を取得するには、JSON 出力を要求します。

```bash
grok -p "Hello" --output-format json | jq -r '.sessionId'
```

## agent stdio でのセッション管理

ACP を使用して構築する場合、セッションはプロトコルメソッドで管理します。

```typescript
// 新しいセッションを作成
const { sessionId } = await connection.request("session/new", {
  cwd: "/path/to/project",
  mcpServers: [],
});

// 既存のセッションを読み込む
await connection.request("session/load", {
  sessionId: "existing-session-id",
  cwd: "/path/to/project",
  mcpServers: [],
});
```

エージェントはすべてのセッション更新を自動的に永続化します。クライアントは再接続し、ID を指定して以前のセッションを読み込めます。

## grok sessions サブコマンド

コマンドラインからセッションを一覧表示または検索します。`grok sessions` にはサブコマンドが必要です。

```bash
# 現在のディレクトリの最近のセッションを一覧表示
grok sessions list

# 結果数を制限（デフォルトは 20）
grok sessions list --limit 50

# キーワードでセッションを検索（タイトルとプロンプトに一致）
grok sessions search "rate limit"
```

`grok sessions list` は、現在の作業ディレクトリのセッションを worktree ラベルごとにグループ化して表示します。各行には、セッション ID、作成日と更新日、ソースの状態、要約が表示されます。`grok sessions search` は、ローカルの SQLite インデックスとリモートの結果を組み合わせます。

---

## Worktree セッション

サブエージェントやセッションフォークを使用する場合、Grok はセッションごとに分離された git worktree を作成できます。各 worktree には作業ディレクトリの独自コピーが割り当てられるため、あるセッションのファイル変更が別のセッションに影響することはありません。

Worktree セッションは、`x.ai/git/worktree/*` 拡張メソッドを通じて内部的に管理されます。主な操作は次のとおりです。

- **作成**: 分離されたセッション用の新しい worktree を作成する
- **適用**: worktree の変更をメインの作業ディレクトリにマージする
- **削除**: セッションの完了時に worktree をクリーンアップする

新しい worktree でセッションを再開するには、`grok -w -r <session-id>` を使用します。

## セッションストレージの詳細

### 永続化形式

Grok は会話を改行区切り JSON（JSONL）として保存します。`updates.jsonl` の各行は、それ自体で完結した ACP セッション更新イベントです。この形式には次の利点があります。

- 増分書き込み（セッション中は追記のみ）
- 効率的なストリーミング読み込み（セッション復元用）
- 容易なデバッグ（各行が有効な JSON）

小さな状態ファイルである `summary.json`、`plan.json`、`signals.json` は、JSONL ではなく通常の JSON です。セッション内容の信頼できる情報源は JSONL です。また、`grok sessions search` は高速なキーワード検索のため、セッションのタイトルとプロンプトを対象としたローカルの SQLite FTS5 インデックスも維持します。

### セッションメタデータ

`summary.json` には、特に次のフィールドが記録されます。

- `info` -- セッション ID と作業ディレクトリ
- `session_summary` と `generated_title` -- セッションの要約と、モデルが生成したタイトル
- `created_at` と `updated_at` -- 作成日時と最終更新日時
- `num_messages` と `num_chat_messages` -- 更新数とチャットメッセージ数
- `current_model_id` -- 使用中のモデル
- `parent_session_id` -- フォークまたは復元元のセッション
- `agent_name` -- セッションの最終保存時に有効だったエージェント定義

### ディスク使用量

多数のファイルを変更するセッションでは、巻き戻しポイントのスナップショット（変更されたファイルのコピー）がディスク使用量の大部分を占めます。履歴のサイズを減らすには `/compact` を使用します。

---

## ヒント

- 現在のコンテキストが不要になったら、`/new` で新しく始めます。
- 長いセッションでは、コンテキストウィンドウを有効に活用できるよう、早めに `/compact` を使用します。
- ミスを取り消すには `/rewind` を使用します。エージェントに以前の状態を再構築させるのではなく、実際のファイルスナップショットを復元します。
- ヘッドレスモードでは、JSON 出力から `sessionId` を取得して `-r` に渡すことで、コンテキストを維持する複数ステップの自動化を構築できます。
- コンテキストウィンドウの使用量を確認するには、`/session-info` を使用します。
