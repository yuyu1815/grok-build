# サブエージェントとペルソナ

サブエージェントは、タスクを並行して処理する独立した子セッションです。各サブエージェントには固有のコンテキストウィンドウがあるため、メインエージェントは自身のコンテキストを消費せずに作業（調査、実装、テスト、コードレビュー）を委任できます。サブエージェントは完了時に親へ要約を返します。

サブエージェントはデフォルトで有効です。

---

## エージェントとペルソナの違い

エージェントとペルソナはどちらも動作をカスタマイズしますが、作用するレベルが異なります。

| | **エージェント** | **ペルソナ** |
|---|---|---|
| **設定対象** | セッション全体: モデル、ツール、プロンプトモード、システムプロンプト | サブエージェントのプロンプトに追加する動作レイヤー |
| **範囲** | プライマリセッションまたはサブエージェント | サブエージェントのみ |
| **設定方法** | 起動時、またはエージェント定義（`.grok/agents/` または `~/.grok/agents/` 内の `.md` ファイル） | `config.toml`（`[subagents.personas]`）または `.grok/personas/` 内の `.toml` ファイル。サブエージェントの解決時に適用 |
| **制御対象** | モデル、使用可能なツール、プロンプト本文、スキル | トーン、出力形式、タスクの焦点、入出力規約 |
| **編集者** | ユーザー。エージェントモーダルまたはファイル編集で作成、削除、有効・無効の切り替えが可能 | ユーザー。設定またはファイルでカスタムペルソナを定義可能。組み込みペルソナは読み取り専用 |
| **例** | `grok-build`、`explore`、`plan` | `researcher`、`concise` |

エージェントはセッション自体を定義します。ペルソナは、セッション内でのサブエージェントの動作を形作ります。サブエージェントは常にエージェントタイプ（例: `general-purpose`）として動作し、解決時にその上へペルソナを重ねられます。

どちらもエージェントモーダルで管理します。`/config-agents`（エイリアス: `/agents`）で開くか、`/personas` で「Personas」タブを直接開きます。モーダルには **Agents** と **Personas** の 2 つのタブがあります。

---

## サブエージェントの無効化

環境変数または設定ファイルでサブエージェントを無効にします。

```bash
export GROK_SUBAGENTS=0              # 環境変数
```

```toml
# ~/.grok/config.toml
[subagents]
enabled = false
```

---

## サブエージェントの仕組み

メインエージェントは委任する作業を特定すると、`spawn_subagent` ツールを呼び出して子セッションを開始します。子は次の構成で動作します。

- 親から独立した固有のコンテキストウィンドウ
- エージェントタイプと任意の機能モードによって決まるツールセット
- 解決時に適用される任意のペルソナ指示

子が完了すると、親は子の出力（通常は要約）を受け取ります。

---

## 組み込みエージェントタイプ

`spawn_subagent` ツールは、子の役割を選択する `subagent_type` パラメーターを受け取ります。

| タイプ            | 説明 |
| ----------------- | ---- |
| `general-purpose` | デフォルトのタイプ。あらゆるタスクに対応する全機能エージェント。 |
| `explore`         | 調査エージェント。検索、読み取り、grep、シェルコマンドの実行は可能ですが、ファイルは編集しません。コードベースの調査に使用します。 |
| `plan`            | 計画エージェント。コードベースを調査して構造化された実装計画を作成しますが、ファイルは編集しません。 |

プロジェクトまたはユーザーが定義したエージェントにより、新しいタイプを追加したり、同名の組み込みタイプを上書きしたりできます。

---

## ペルソナ

ペルソナは、名前付きの動作レイヤーです。その指示は `<system-reminder>` としてサブエージェントの会話に挿入され、サブエージェントのエージェントタイプ、モデル、ツールを変更せずに、トーン、出力形式、タスクの焦点を調整します。

ペルソナは `config.toml` または `.toml` ファイルで定義します。

```toml
[subagents.personas.researcher]
instructions = "You are a thorough researcher. Always cite specific file paths."
description = "Deep investigator."
```

Grok Build は、次の場所からファイルベースのペルソナを優先度順に検出します。

- `.grok/personas/*.toml`（プロジェクト）
- `~/.grok/personas/*.toml`（ユーザー）
- 組み込みペルソナのディレクトリ（優先度が最も低い）

各ファイルで 1 つのペルソナを定義し、拡張子を除いたファイル名がペルソナ名になります。`config.toml` 内のインラインペルソナは、ファイルより優先されます。検出対象は `.toml` ファイルのみです。

エージェントモーダルの「Personas」タブ（`/personas`）でペルソナを管理します。組み込みペルソナは読み取り専用ですが、ユーザーが定義したペルソナは編集できます。

> **注:** Grok Build は、`spawn_subagent` パラメーターではなく、サブエージェントの解決とロールを通じてペルソナを適用します。メインエージェントは、子を起動するときにペルソナ名を渡しません。

### ペルソナのフィールド

| フィールド          | 説明 |
| ------------------- | ---- |
| `instructions`      | ペルソナレイヤーとして適用するインライン指示テキスト。 |
| `instructions_file` | 起動時に読み込み、`instructions` の後へマージする指示ファイルのパス。 |
| `description`       | ペルソナカタログに表示する短い要約。未指定の場合は `instructions` の最初の段落を使用。 |
| `inputs` / `outputs`| 宣言された入出力規約（下記参照）。 |
| `model`             | ペルソナ使用時に適用するモデルの上書き。 |
| `reasoning_effort`  | ペルソナ使用時に適用する推論の強度。 |
| `default_isolation` | デフォルトの分離モード（`none` または `worktree`）。 |

### 入出力規約

ペルソナは、想定する入力と生成する出力を宣言できます。親エージェントはこれらを参照し、渡すべきコンテキストと期待する成果物を把握します。これにより、あるペルソナの出力ファイルを次のペルソナの入力にするなど、ペルソナを連鎖できます。

```toml
[[subagents.personas.reviewer.inputs]]
name = "review_file"
io_type = "file"
required = true
description = "Path to the code under review"

[[subagents.personas.reviewer.outputs]]
name = "summary_file"
io_type = "file"
required = false
description = "Path to write review notes"
```

各フィールドには `name`、`io_type`（デフォルトは `file`）、`required` フラグ、`description` があります。

### ペルソナの解決

ペルソナを適用する場合、Grok Build は有効なモデルと推論の強度を次の優先順位で解決します。

1. 起動時の明示的な上書き
2. ロールのデフォルト
3. ペルソナのデフォルト
4. 親セッション

分離についても最初の 3 段階は同じ順序ですが、親セッションから継承せず、デフォルトは `none`（worktree なし）です。

要求されたペルソナを解決できない場合（見つからない、指示がない、`instructions_file` を読み取れないなど）、起動は失敗します。

## サブエージェントの起動

メインエージェントは `spawn_subagent` ツールを呼び出します。パラメーターは次のとおりです。

| パラメーター      | 説明 |
| ----------------- | ---- |
| `prompt`          | サブエージェントに渡す完全なタスクプロンプト。 |
| `description`     | タスクを表す短いラベル（3～5 語）。 |
| `subagent_type`   | 起動するエージェントタイプ。デフォルトは `general-purpose`。 |
| `background`      | サブエージェントをバックグラウンドで実行し、サブエージェント ID をすぐに返す。デフォルトは `false`。 |
| `capability_mode` | サブエージェントのツールを `read-only`、`read-write`、`execute`、`all` のいずれかに制限。 |
| `isolation`       | `none`（共有ワークスペース、デフォルト）または `worktree`（分離された git worktree）。 |
| `resume_from`     | 完了したサブエージェントの会話を継続する。サブエージェント ID を指定。 |
| `cwd`             | サブエージェントの作業ディレクトリ。`isolation: worktree` とは併用不可。`resume_from` の設定時は無視され、再開した子は元の子のディレクトリを継承。 |

サブエージェントをバックグラウンドで実行した場合は、後から `get_command_or_subagent_output` で結果を取得します。

---

## 機能モード

機能モードは、サブエージェントのツールに適用する任意の大まかなフィルターです。

| モード       | 読み取り | 書き込み | 実行 | 説明 |
| ------------ | -------- | ---------- | ---- | ---- |
| `read-only`  | 可       | 不可       | 不可 | 読み取り、検索、調査（Web 検索と LSP を含む）が可能。ファイル編集とシェルは不可。 |
| `read-write` | 可       | 可         | 不可 | 読み取りに加え、ファイルの作成、編集、削除、移動が可能。シェルは不可。 |
| `execute`    | 可       | 不可       | 可   | 読み取りに加え、シェルコマンドとバックグラウンドタスクの実行が可能。ファイル編集は不可。 |
| `all`        | 可       | 可         | 可   | ツールへのアクセス制限なし。 |

`capability_mode` を省略すると、サブエージェントはエージェントタイプのツールセットを使用します。組み込みの `explore` と `plan` タイプは、読み取り、検索、シェルコマンドの実行はできますが、ファイルは編集できません。`general-purpose` にはすべてのツールが用意されています。

## コンテキストの継承

### resume_from

`resume_from` パラメーターを使用すると、新しいサブエージェントが完了済みサブエージェントの続きから作業できます。複数段階のワークフローに便利です。

1. 問題を調査するサブエージェントを起動する。
2. 2 番目のサブエージェントを起動し、`resume_from` に最初のサブエージェントの ID を設定して、調査の全コンテキストを引き継ぐ。

新しいサブエージェントは、元の子のトランスクリプト、ツール状態、モデルを継承します。システムプロンプトとツールは、現在のエージェント定義から再生成されます。元の子は完了済み（実行中ではない）で、現在のセッションに属し、同じエージェントタイプを使用している必要があります。

---

## 分離: Worktree モード

ファイルを変更するタスクでは、`isolation: worktree` を指定し、分離された git worktree でサブエージェントを実行します。これにより、子の編集が親と競合するのを防げます。

- サブエージェントは作業ツリーの独自コピーで作業します。
- 変更をマージするまで、子の変更は親から分離されたままです。
- サブエージェントの結果には worktree のパスが含まれます。

Grok Build は `x.ai/git/worktree/*` 拡張メソッドで worktree を管理します。これには、変更をメインの作業ディレクトリへマージする apply 操作も含まれます。

## 設定

### タイプごとの有効・無効設定とモデルの上書き

特定のエージェントタイプを無効にしたり、別のモデルへ振り分けたりできます。

```toml
[subagents.toggle]
explore = true                       # デフォルト。有効のままにする場合は省略可能
plan = false                         # plan サブエージェントを無効化

[subagents.models]
explore = "grok-build"               # explore を特定のモデルへ振り分け
```

タイプごとのモデル上書きは、どの親にも適用されます。上書きがない場合、サブエージェントは親のモデルを継承します。

### カスタムロールとペルソナ

独自の機能とモデルのデフォルト値を持つカスタムロールを定義します。

```toml
[subagents.roles.researcher]
description = "Deep research agent"
default_capability_mode = "read-only"
model = "grok-build"
prompt_file = ".grok/prompts/researcher.md"
```

動作指示を持つカスタムペルソナを定義します。

```toml
[subagents.personas.concise]
instructions = "Be concise. No filler words."
# instructions_file = ".grok/personas/concise.md"  # またはファイルから読み込む
```

Grok Build は、`.grok/roles/*.toml` からロールを、`.grok/personas/*.toml` からペルソナを検出します。`config.toml` 内のインライン定義は、ファイルより優先されます。

## タスクペイン（TUI）

Grok Build は、実行中および完了した作業をエージェント画面のサイドペインに表示します。

- `Ctrl+B` を押すとタスクペインの表示を切り替えられます。ここには実行中および完了済みのサブエージェントとバックグラウンドコマンドが、その状態とともに一覧表示されます。
- `Ctrl+T` を押すと、独立した TODO ペインの表示を切り替えられます。

使用可能なエージェントタイプとペルソナを確認するには、`Ctrl+P` でコマンドパレットを開き、**Manage Agents**（`/config-agents`）を選択します。

サブエージェントは、タスクペインの上部にある折りたたみ可能な「Subagents」グループ内に表示されます。

---

## TUI でのサブエージェントの表示

インタラクティブ TUI では、サブエージェントが複数の場所に表示されます。

### スクロールバック（親の会話履歴）

サブエージェントが起動すると、*親*のスクロールバックに簡潔なライフサイクルブロックが追加されます。

- `Subagent running: "do the thing" (Implementer · grok-3) — Thinking`
- バックグラウンドサブエージェントの場合: `Subagent started: "..."`

実行中は、子のターントラッカーから取得した現在のアクティビティを表す接尾辞（例: 「Running: cargo test」、「Compacting」、「Retrying (2/3)」）がブロックに表示されます。状態に応じてステータス表示の点がアニメーション表示（または色分け）されます。

ブロック上で **Enter**（または Ctrl-F）を押すと、サブエージェントの完全なトランスクリプトが開きます。

ブロッキング実行のサブエージェントでは、子の完了時に単一エントリのステータス表示の点の色が更新されます。バックグラウンド実行の場合は、後続の `Subagent completed/failed/cancelled in Xs: "..."` ブロックが追加されます。

### タスクペイン（Ctrl+B）

前述のとおり、「Subagents」の下にまとめられ、スピナー、経過時間、強制終了または詳細表示へのクイックアクセスが表示されます。

### 全画面フレーム表示（子のトランスクリプト）

スクロールバックのブロックまたはタスクペインからサブエージェントを開くと、親の表示が、子の完全なトランスクリプトを含む枠付きフレームに置き換わります。

- フレーム内のタイトルバー: 状態アイコン（スピナー / ✓ / ✗）、ラベル + 太字の説明 + モデル、任意の「resumed」/「forked」バッジ、現在のアクティビティ · 経過時間、[✗] 閉じるボタン。
- 子自身のスクロールバック、思考、ツール呼び出し、（制限された）プロンプト領域がフレーム内に表示されます。
- サブエージェント表示は主に観察用です。通常、親セッションと同じように新しいトップレベルプロンプトを直接送信することはできません。

`q`、`Esc`、または閉じるボタンを使用して親の表示へ戻ります。親のスクロールバックには、引き続きサブエージェントの状態が表示されます。

## 深さの制限

サブエージェントを起動できるのはトップレベルセッションのみです。サブエージェントが別のサブエージェントを起動することはできず、最大ネスト深度は 1 です。サブエージェントが `spawn_subagent` を呼び出すと、深さ制限エラーで失敗します。これにより、エージェントツリーをフラットに保ち、際限のない起動を防ぎます。

## サブエージェントを使用する場面

**適している場面:**

- 親が他の作業を続けている間にコードベースを調査する
- 親が変更を実装している間にテストを並行実行する
- コミット前に生成された変更をレビューする
- 相互に依存しない独立したタスクを委任する

**適していない場面:**

- 親が直接処理できる単純なタスク
- サブエージェントは自律的に動作し、対話的なやり取りには適さないため、ユーザーとの緊密な往復が必要なタスク
- コンテキストを準備するコストが並列化の利点を上回るタスク
