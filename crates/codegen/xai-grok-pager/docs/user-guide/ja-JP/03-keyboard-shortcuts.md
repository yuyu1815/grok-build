# キーボードショートカット

Grok Build TUI のキーバインド一覧です。現在、バインドは組み込みで、変更できません。

---

<a id="input-modes"></a>

## 入力モード

Grok には、スクロールバック内の移動方法を制御する 2 つの入力モードがあります。

- **シンプルモード**（デフォルト）: 矢印キーで移動し、`Shift+Arrow` でターン間を移動します。`Space` でプロンプトにフォーカスし、文字キーを押すと自動でプロンプトにフォーカスします。
- **Vim モード**（任意）: `j`/`k` で移動、`H`/`L` でターン間を移動、`J`/`K` で応答間を移動、`h`/`l` で折りたたみ、`e`/`E` で展開・折りたたみ、`i`/`Tab`/`Space` でプロンプトにフォーカスします。

デフォルトではシンプルモードが有効です。Vim モードに切り替えるには、`~/.grok/config.toml` の `[ui]` で `vim_mode = true` を設定するか、実行中に `/vim-mode` で切り替えます。詳しくは[設定](05-configuration.md)を参照してください。

以下の表では、両方のモードのバインドを説明します。「キー」列は Vim モードのバインド、「代替キー」列はシンプルモードで対応するキー（矢印キーなど）です。

> **Vim モードが必要**: **スクロールバック**で使う文字単独および
> `Shift+letter` のバインド（`j/k`、`h/l`、`g/G`、`L/H`、`y/Y`、`o/O`、`r`、
> `x`、`e/E`、挿入モード用の代替キー `i`）には、`~/.grok/config.toml` で
> `[ui].vim_mode = true` を設定する必要があります（または `/vim-mode` で切り替えます）。
> 矢印キー、`Tab`、`Esc`、`Space`、`PageUp/Down`、すべての `Ctrl+letter`
> ショートカットは、どちらのモードでも使えます。

## 移動（スクロールバックにフォーカス）

スクロールバックペイン内の会話項目間を移動します。

| キー | 代替キー | 操作 |
|-----|---------|--------|
| `j` | `Down` | 次の項目を選択 |
| `k` | `Up` | 前の項目を選択 |
| `⇧L` | `Shift+Right` | 次のターン（ユーザープロンプト）へ移動 |
| `⇧H` | `Shift+Left` | 前のターン（ユーザープロンプト）へ移動 |
| `⇧J` | | 次のアシスタント応答へ移動 |
| `⇧K` | | 前のアシスタント応答へ移動 |
| `g` | | スクロールバックの先頭へ移動 |
| `⇧G` | | スクロールバックの末尾へ移動 |
| `Ctrl+K` | | 選択を変えずに 1 行上へスクロール |
| `Ctrl+J` | | 選択を変えずに 1 行下へスクロール |
| `PageUp` | | 1 ページ上へスクロール（選択項目は表示領域の先頭へ移動） |
| `PageDown` | | 1 ページ下へスクロール（選択項目は表示領域の末尾へ移動） |
| `Ctrl+U` | | 半ページ上へスクロール |
| `Ctrl+D`（VSCode では `Shift+D`） | | 半ページ下へスクロール |

通常のプロンプトにフォーカスしている間も、`PageUp` と `PageDown` でフォーカスや下書きを変えずに会話をスクロールできます。プロンプト履歴、`@` ファイル検索、スラッシュメニュー、補完ドロップダウンが開いている場合、これらのキーは各機能内の移動に使われます。

## 表示（スクロールバックにフォーカス）

スクロールバック内の項目の表示方法を制御します。

| キー | 代替キー | 操作 |
|-----|---------|--------|
| `h` | `Left` | 選択項目を折りたたむ |
| `l` | `Right` | 選択項目を展開 |
| `e` | | 選択項目の折りたたみ状態を切り替える |
| `⇧E` | | すべての項目を展開／折りたたむ |
| `Ctrl+E` | | すべての思考ブロックを展開／折りたたむ |
| `r` | | 選択項目の Markdown ソース表示を切り替える |

`pager.toml` の `[scrollback.scroll]` で `respect_manual_folds = true` を設定すると（任意、デフォルトは無効。詳しくは[設定](05-configuration.md)を参照）、手動で折りたたんだブロックの状態が固定されます。ストリーミング更新や完了イベント（思考ブロックの終了など）でも状態はリセットされません。また、自動スクロールで末尾を追跡中にブロックを展開すると追跡が停止し、その内容を読めます。追跡を再開するには、`⇧G` を押す、最後の項目で `j` を押す、末尾より下へスクロールする、または新しいプロンプトを送信します。`⇧E` はすべての固定を解除し、`Ctrl+E` は思考ブロックの固定を解除します。

<a id="block-content"></a>

### ブロックの内容

| キー | 操作 |
|-----|--------|
| `y` | ブロックの内容をクリップボードへコピー |
| `⇧Y` | ブロックのメタデータ（シェルコマンドなど）をクリップボードへコピー |
| `Enter` | ブロックの内容を全画面ビューアーで開く |
| `Ctrl+F` | ブロックの内容を全画面ビューアーで開く（代替バインド） |

<a id="focus"></a>

## フォーカス

プロンプト入力とスクロールバックペインの間でフォーカスを切り替えます。

| キー | 代替キー | 状況 | 操作 |
|-----|---------|---------|--------|
| `Tab` | `Space`（Vim モードでは `i` も可） | スクロールバックにフォーカス | プロンプト入力にフォーカス |
| `Tab` | | プロンプトにフォーカス | スクロールバックにフォーカス（シンプルモードと Vim モードの両方） |
| `Enter` | | プロンプトにフォーカス | 現在のプロンプトを送信 |

**Esc はフォーカスキーではありません。** `[ui].simple_mode`（プロンプトエディター）や `[ui].vim_mode`（スクロールバック移動）の設定にかかわらず、以下の消去／巻き戻し動作に従います（ターン実行中は入力を処理せず吸収します）。ただし、オーバーレイ、モーダル、スラッシュ／ファイルのドロップダウン、音声、検索、選択は先に Esc を処理します。

<a id="escape"></a>

## Esc

| 状態 | 操作 | 結果 |
|--------|---------|--------|
| ターン実行中 | `Esc` | 何もせず吸収（キャンセル**しません**）。`Ctrl+C`（またはパレットなどのキャンセル手段）を使います。 |
| ターンのキャンセル中 | `Esc` | キャンセルを再送（最初の確認応答が失われた場合の再試行）。この状態で `Ctrl+C` を押すと、終了処理へ進みます。 |
| 待機中 + プロンプトが空でない（テキストまたは画像チップ）、**プロンプトにフォーカス** | **800 ミリ秒以内に `Esc` を 2 回** | プロンプトを消去します。空でないテキストはプロンプト履歴に保存されます。1 回目には「もう一度押すと消去」と表示されます。 |
| 待機中 + プロンプトが空 + 会話メッセージあり、**プロンプトまたはスクロールバックにフォーカス** | **800 ミリ秒以内に `Esc` を 2 回** | 巻き戻し選択画面を開きます（`/rewind` と同じ）。1 回目は何も表示されません（トーストなし）。 |
| 待機中 + 空 + メッセージなし、**または下書き／モード付き（`!`、`#`、フィードバック）コンポーザー／応答待ちの needs-input オーバーレイ／履歴検索が開いた状態でスクロールバックにフォーカス** | `Esc` | 何もせず吸収（スクロールバックにはフォーカスしません）。消去はプロンプトペインでのみ行えます。巻き戻しには、空の Normal モードのコンポーザー、保留中のオーバーレイなし、履歴検索なし、という条件が必要です。スクロールバックを読んでいるだけでは、下書き、コンポーザーモード、回答待ちの質問、進行中の検索は変更されません。 |

**Esc の優先処理（ターン中の吸収／消去／巻き戻しより先に実行）:** オーバーレイ、モーダル、スラッシュ／ファイル／補完ドロップダウン、履歴検索、スクロールバック検索、テキスト選択、リンク強調表示、音声、およびプロンプトが空の場合の **Bash／Remember／Feedback モード終了**（Esc で `!`／`#`／フィードバックモードを抜け、通常のプロンプトへ戻ります。ターン実行中も同様です）。

**Ctrl+C と Esc の違い:** ターン実行中に空でない下書きがある場合、Ctrl+C は下書きを消去してターンを継続します。空のプロンプトでもう一度 Ctrl+C を押すとキャンセルします。Esc は実行中のターンをキャンセルしません（すでにキャンセル中の場合のみ再試行します）。待機中に空でないプロンプトで Ctrl+C を押すと 1 回で消去しますが、Esc は 800 ミリ秒以内に 2 回押す必要があります。

## エージェント単位

エージェント画面から利用でき、エージェントセッションに影響する操作です。

| キー | 状況 | 操作 |
|-----|---------|--------|
| `Ctrl+P` | エージェント画面 | コマンドパレットを開く |
| `?`（Shift+/） | エージェント画面 | コマンドパレットを開く（代替バインド） |
| `Ctrl+M` | エージェント画面 | モデル選択画面を開く／モデルを切り替える |
| `Ctrl+M` | プロンプトにフォーカス | 複数行入力モードを切り替える |
| `Ctrl+C` | エージェント画面 | 現在のターンをキャンセル（空でない下書きがある場合は先に消去。Esc の表を参照） |
| `Ctrl+O` | エージェント画面 | 常時承認（YOLO）モードを切り替える |
| `Ctrl+S` | エージェント画面 | セッション選択画面を開く（以前のセッションを再開） |
| `Ctrl+;`（代替: `Ctrl+'`） | エージェント画面 | プロンプトキューペインを切り替える（空でない場合）。**ローカル macOS** の VS Code 系のみ、メインは **`Ctrl+4`**（`;`／`'` も代替として使用可）。SSH と Mac 以外では **`Ctrl+;`**／**`Ctrl+'`**。 |
| `Shift+Tab` | プロンプトにフォーカス | モードを順に切り替える（Normal → Plan → Always-approve） |
| `Ctrl+G` | エージェント画面 | 現在のタスクをバックグラウンドへ移す |
| `Ctrl+T` | エージェント画面 | Todo ペインを切り替える |
| `Ctrl+B` | エージェント画面 | タスクペインを切り替える |
| `Ctrl+L` | エージェント画面 | 拡張機能モーダルを開く（**VS Code 系以外のみ**。VS Code／Cursor／Windsurf／Zed では、ターン中の `Ctrl+L` は**割り込み**。拡張機能は `/plugins`／`/hooks` から開きます） |
| `↑` | プロンプトにフォーカス（空のプロンプト、通常入力モード） | 最後のプロンプトを入力した状態で履歴パネルを開きます。`↑`／`↓` で項目間を移動し（各項目が入力欄に入ります）、最新項目で `↓` を押すとパネルが閉じます。入力すると呼び出したプロンプトをその場で編集できます。呼び出した `!` シェルコマンドはシェルモードに戻ります。`↓` では履歴を開きません。 |
| `!` | プロンプトにフォーカス | シェルモードに入る（空のプロンプトで `!` を入力） |
| `Ctrl+.`（代替: `Ctrl+X`） | エージェント画面 | キーボードショートカットのヘルプを開く |
| `F2`（代替: `Ctrl+,`／`Cmd+,`） | エージェント画面 | 設定モーダルを開く |

**注:** `Ctrl+M` の動作は状況によって変わります。プロンプトにフォーカスしている場合は複数行入力モードを切り替え、それ以外ではモデル選択画面を開きます。

**注:** `Ctrl+'` は Windows での `Ctrl+;` の代替です。一部の Windows コンソールでは、記号キーの `Ctrl` 修飾が失われます。

**注:** `Ctrl+.` には Kitty keyboard protocol（または、プロトコルを通すための tmux `extended-keys on`）が必要です。VS Code／Cursor／Windsurf／Zed の統合ターミナル、VTE、Apple Terminal、Windows Terminal、JetBrains、`extended-keys off` の tmux、screen など、KKP 非対応の環境では、代わりに **`Ctrl+X`** がショートカット一覧のメインキーとして表示されます。**`Ctrl+X` は従来の制御文字として、`Ctrl+.` が使えない環境でも常に機能します。** tmux で修飾キーが正しく動作しない場合は、`/terminal-setup` を実行してください。

## 画像の貼り付けとドラッグ＆ドロップ

| 操作 | macOS | Linux | Windows |
|---|---|---|---|
| ファイルマネージャーからプロンプトへ画像をドラッグ | Finder ✓ | Files／Dolphin ✓ | Explorer ✓ |
| ファイルマネージャーでファイルをコピーして貼り付け | `Cmd+V` | `Ctrl+V` | `Ctrl+V` |
| クリップボード内のスクリーンショットまたは「画像をコピー」を貼り付け | `Cmd+V` | `Ctrl+V` | **`Alt+V`** |

画像以外のファイルは、チップではなく絶対パスのテキストとして挿入されます。

> **Windows の `Alt+V`** は Grok 固有です。Windows Terminal のデフォルトの `Ctrl+V` はプレーンテキストのみを貼り付け、画像のクリップボードを通知なしで破棄します。`Alt+V` はこの割り込み処理を回避します。画像にも `Ctrl+V` を使うには、Windows Terminal の `settings.json` の `actions` に `{ "command": null, "keys": "ctrl+v" }` を追加してください。

<a id="linux-primary-and-clipboard"></a>

### Linux の PRIMARY と CLIPBOARD

Linux X11 には、独立した 2 つのテキスト選択領域があります。

- `Ctrl+V` は、明示的なコピー／切り取り用の **CLIPBOARD** を読み取ります。PRIMARY へフォールバックすることはありません。`xclip` でテキストを格納するには、`printf %s "text" | xclip -selection clipboard` を使います。
- Grok で修飾キーなしの中クリックを行うと、`DISPLAY` が空でない場合に限り、現在マウスで選択している **PRIMARY** を読み取ります。純粋な X11 ではネイティブの読み取り機能へフォールバックできます。XWayland では、Wayland の PRIMARY ではなく X11 の選択領域を Grok が読み取れるよう、`PATH` 上に `xclip` または `xsel` が必要です。押下は 1 回だけ処理され、ボタンを離しても再度貼り付けられません。
- `Shift+Insert` は、選択したテキストを貼り付けるターミナル標準の方法です。多くのターミナルでは、`Shift+middle click` でもアプリケーションのマウス処理を回避できます。

SSH 経由では通常、リモートの Grok プロセスからターミナル側のローカル X11 選択領域へアクセスできません。ターミナル標準の `Shift+Insert` または `Shift+middle click` を使い、ローカルターミナルから選択テキストを PTY 経由で送信してください。

<a id="during-an-active-turn-agent-running"></a>

## ターン実行中（エージェント稼働中）

エージェントが生成中の場合:

- **通常の `Enter`** は、コンポーザーにテキストがあるとフォローアップを後で実行するために**キューへ追加**します。キュー内のフォローアップは現在のターンの終了後に実行されます。ただし、エージェントがバックグラウンドタスクやサブエージェントを待って停止している間は、意図的に**保留**されます（保留の理由とすぐに送る方法がヒントに表示されます）。
- 空になったコンポーザーで**もう一度 `Enter`** を押す（Enter を 2 回押す）と、キューの**先頭**のフォローアップをすぐに送信します。
- **今すぐ送信**のキー操作は、**キャンセルして送信**します。現在のターンを停止し（バックグラウンドタスク、サブエージェント、残りのキューは実行を継続）、メッセージを次のターンとして送信するため、常にトランスクリプトの末尾に表示されます。
  - **空でないコンポーザー** → キャンセルし、そのテキストを今すぐ送信します。
  - **空のコンポーザー** + キュー内のフォローアップ → キューペインにフォーカスしなくても、**先頭**のフォローアップを今すぐ送信します。キューペインでは、同じキー操作（または **[今すぐ送信]** ボタン）で**選択中**の行を送信します。
  - **待機中**、または**空のコンポーザーかつキューが空** → そのキーでは何も起こりません。
- エージェントがタスク出力やサブエージェントを**待って停止中**の場合、テキストを入力して通常の `Enter` を押してもすぐに送信されます。シェルは停止中のターンをキャンセルし、次にメッセージを実行します。

| ターミナル | メイン | 代替 | 操作 |
|----------|---------|------------|--------|
| デフォルト | `Ctrl+Enter` | `Ctrl+I` | 今すぐ送信（現在のターンをキャンセルし、次にメッセージを実行） |
| Apple Terminal | `Ctrl+O` | `Ctrl+Enter`、`Ctrl+I` | 今すぐ送信 |
| VS Code 系（VS Code、Cursor、Windsurf、Zed） | **`Ctrl+L`** | *なし* | 今すぐ送信（`Ctrl+I` は不使用 — Tab／ホストのチャット用。プラグインは `/plugins` から開く） |

`/multiline` モードでは、`Shift+Enter`（または `Alt+Enter`）で送信し、通常の `Enter` で改行を挿入します。ただし、ターン中にコンポーザーが**空**でキューにフォローアップがある場合、通常の `Enter` でも先頭行を**今すぐ送信**します（通常モードと同じ）。非 VS Code 系でバインドされている場合、`Ctrl+Enter` はターン中の今すぐ送信に使われます。待機中の新しいターンは送信しません。

「今すぐ送信」は意図的に割り込みを行い、「今していることを止めて、これに対応して」という意味になります。エージェントを停止せずにメモを渡すには、通常の `Enter` でキューへ追加してください。エージェントは次のターン境界で受け取ります。

> **WezTerm**: これらの修飾付き Enter キーを使うには、WezTerm の設定で `enable_kitty_keyboard = true` が必要です。詳しい手順と 1 行の回避策は、[ターミナルサポートガイド](21-terminal-support.md#problem-ctrlenter-doesnt-interject-in-wezterm)を参照してください。

> **Windows（VS Code 系以外）**: 一部のコンソールでは `Ctrl+Enter` の `Ctrl` 修飾が失われ、通常の `Enter` または `Ctrl+J` として扱われることがあります。代替の `Ctrl+I` を使ってください。文字キーの Ctrl キー操作は、どの環境でも安定しています。VS Code 系では **`Ctrl+L`** を使います。

> **VS Code 系の `Ctrl+L`**: Grok はこのキーを割り込みに使い、拡張機能のショートカットには割り当てません（プラグインは `/plugins` またはコマンドパレットから開きます）。ターミナルプロファイルで **Clear**（または別のコマンド）が `Ctrl+L` に割り当てられていると、ホスト側でキー操作が奪われる場合があります。PTY が form feed（`\x0c`）を受信できるよう、そのバインドを変更または削除してください。

<a id="global"></a>

## グローバル

どの画面からでも利用できる操作です。

| キー | 代替キー | 操作 | 確認 |
|-----|---------|--------|-------------|
| `Ctrl+N` | | 新しいセッションを作成（必要に応じて git worktree 内に作成） | あり（1000 ミリ秒以内に 2 回押す） |
| `Ctrl+Q` | `Ctrl+D` | アプリケーションを終了 | あり（1000 ミリ秒以内に 2 回押す） |

**VS Code 系ターミナル**（VS Code、Cursor、Windsurf、Zed の統合ターミナル）: `Ctrl+Q` はホストに取得されるため、Grok では **`Ctrl+D` が唯一の終了キー**です（`Ctrl+Q` は未割り当て）。半ページ下への移動は、修飾キーなしの **`Shift+D`** に再割り当てされます。`Ctrl+Enter`／`Ctrl+I` は確実に PTY へ届かないため、ターン中の割り込みには **`Ctrl+L`** のみを使います。拡張機能は `Ctrl+L` ではなく `/plugins` から開きます。

> **ウェルカム画面へ戻るキーバインドはありません。** セッション内から `/home` スラッシュコマンド（別名 `/welcome`）を使ってください。[スラッシュコマンド](04-slash-commands.md)を参照してください。

<a id="destructive-action-confirmation"></a>

### 破壊的操作の確認

確認列が「あり」の操作は、1000 ミリ秒以内に 2 回押す必要があります。キーを 1 回押すと確認メッセージが表示され、もう一度押すと確定します。これにより、誤ってセッションを失うことを防ぎます。

<a id="welcome-screen"></a>

## ウェルカム画面

エージェントセッションを開く前のウェルカム画面でのみ動作するバインドです。

| キー | 操作 |
|-----|--------|
| `Ctrl+S` | セッションを再開（セッション選択画面を開く） |
| `Ctrl+W` | New Worktree ダイアログを開く（git リポジトリ内のみ） |
| `Ctrl+I` | Claude の設定をインポート（利用可能な場合） |
| `Ctrl+Shift+I` | Claude のインポート行を閉じる（利用可能な場合） |

`Ctrl+W`、`Ctrl+I`、`Ctrl+Shift+I` はウェルカム画面でのみ有効です。`Ctrl+S` はウェルカム画面とエージェントセッション内の両方でセッション選択画面を開きます（エージェントセッション内では、`/resume` コマンドと同じモーダルオーバーレイとして開きます）。`Ctrl+Q` は上記のグローバルな終了バインドであり、ウェルカム画面専用の処理ではありません。

<a id="command-palette"></a>

## コマンドパレット

`Ctrl+P` または `?` を押すと、検索可能な操作一覧であるコマンドパレットが開きます。パレットには次の項目が表示されます。

- 現在のバインドを含む、すべてのキーボードショートカット
- すべてのスラッシュコマンド
- 利用可能なスキル

入力して絞り込み、`Enter` を押すと選択した操作を実行します。

<a id="shortcuts-bar"></a>

## ショートカットバー

TUI の下部には、現在の状態に最も関連するキーバインドを示すショートカットバーが表示されます。ヒントは次の条件に応じて変わります。

- フォーカスしているペイン（スクロールバックまたはプロンプト）
- エージェントが実行中かどうか
- 選択している項目の種類

<a id="mouse-support"></a>

## マウス操作

TUI は次のマウス操作に対応しています。

- スクロールバック項目を**クリック**して選択
- **スクロールホイール**でスクロールバック内を移動
- プロンプト領域を**クリック**してフォーカス
- プロンプトに**カーソルを重ねて**強調表示（`pager.toml` で設定可能）
- Linux X11／XWayland で**middle click**して PRIMARY 選択領域を貼り付け

<a id="quick-reference-card"></a>

## クイックリファレンス

<a id="when-scrollback-is-focused-simple-mode--default"></a>

### スクロールバックにフォーカスしている場合（シンプルモード — デフォルト）

```
移動:                 Up/Down（前／次の項目）  Shift+Left/Right（前／次のターン）
スクロール:           Ctrl+J/K（行）  PgUp/PgDn（ページ）  Ctrl+U/D（半ページ）
プロンプトにフォーカス: Space または任意の文字キー（自動でフォーカスして入力）
```

<a id="when-scrollback-is-focused-vim-mode"></a>

### スクロールバックにフォーカスしている場合（Vim モード）

```
移動:                 j/k（上／下）  H/L（前／次のターン）  K/J（前／次の応答）  g/G（先頭／末尾）
スクロール:           Ctrl+J/K（行）  Ctrl+U/D（半ページ。VSCode では D=Shift+D）  PgUp/PgDn（ページ）
折りたたみ:           h/l（折りたたむ／展開）  e（切り替え）  E（すべて）
内容:                 y（コピー）  Y（コマンドをコピー）  Enter（全画面）
表示:                 r（Markdown ソース）  Ctrl+E（思考ブロック）
プロンプトにフォーカス: i、Tab、または Space
```

<a id="when-prompt-is-focused"></a>

### プロンプトにフォーカスしている場合

```
送信:                 Enter
改行:                 Shift+Enter または Alt+Enter
複数行入力:           Ctrl+M（切り替え）
貼り付け:             Ctrl+V（テキスト、ファイル、macOS/Linux のスクリーンショット）
選択テキスト:         中クリックまたは Shift+Insert（Linux X11/XWayland の PRIMARY）
画像を貼り付け:       Alt+V（Windows のみ — スクリーンショット／「画像をコピー」）
すべて選択:           Cmd+A（macOS、Ghostty のみ — 下記の注を参照）
離れる:               Tab（スクロールバックへ戻る）
キャンセル（実行中）: Ctrl+C（空のプロンプト。空でない下書きは先に消去）
消去（待機中）:       800 ミリ秒以内に Esc Esc（空でないプロンプト）
巻き戻し（待機中）:   800 ミリ秒以内に Esc Esc（空のプロンプト + メッセージ）
```

> **Cmd+A は Ghostty でのみ有効です。** Grok 内の `Cmd+A` 処理は、検出されたターミナルが Ghostty の場合にのみ有効になります。ほかのターミナルでは、ターミナル側で `Cmd+A` を吸収するか（Apple Terminal、デフォルトの iTerm2）、ターミナル独自の「すべて選択」を実行します（Kitty、WezTerm）。Ghostty 以外ではこのバインドは何もせず、キー入力はターミナル標準の動作へ渡されます。
>
> Ghostty では、キー入力が実行中の TUI へ届くよう、`~/.config/ghostty/config` に次の 1 行を追加してバインドを解除してください。
>
> ```ini
> keybind = cmd+a=unbind
> ```
>
> Ghostty が設定を再読み込みすると（設定ファイルは監視されています）、プロンプト内の `Cmd+A` で、貼り付けた画像チップを含むプロンプトバッファ内のすべての文字を選択できます。画像チップには常にパスが含まれません（`[Image #N]`）。ファイルパスが判明している場合でも、チップにカーソルを重ねるか、カーソルをチップ上または直後に置いたとき、画像プレビューのオーバーレイにのみ表示されます。
